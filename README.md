# Movies API V2

Учебный REST API на FastAPI для управления фильмами.

Для хранения данных используется SQLite, взаимодействие с базой данных выполняется с помощью SQLAlchemy. Валидация входных данных осуществляется через Pydantic.

Жанры фильма (`genres`) и актёрский состав (`casts`) хранятся в базе данных в формате JSON-массивов.

## Установка и запуск

1. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Запустите сервер:

   ```bash
   uvicorn main:app --reload
   ```

3. Откройте Swagger UI:

   http://127.0.0.1:8000/docs


При первом запуске приложения таблица `movies` создаётся автоматически. Файл базы данных `movies.db` также создаётся автоматически при подключении к SQLite.

## Запуск в Docker

В контейнере сервер использует порт `8000`.

1. Соберите Docker-образ:

   ```bash
   docker build -t move-service .
   ```


2. Запустите контейнер:

   ```bash
   docker run -d \
     -p 8000:8000 \
     move-service
   ```

Документация API будет доступна по адресу:

http://localhost:8000/docs

Docker Volume `movies-data` используется для постоянного хранения файла SQLite. Данные сохраняются при остановке, удалении и повторном создании контейнера, если при запуске подключается тот же Volume.

## Эндпоинты

| Метод | Путь | Параметр | Описание |
|---|---|---|---|
| POST | `/` | JSON в теле запроса | Добавить новый фильм. Возвращает созданную запись с идентификатором. |
| GET | `/` | — | Получить список всех фильмов. |
| GET | `/{movie_id}` | `movie_id` в пути | Получить фильм по идентификатору. |
| PUT | `/{movie_id}` | `movie_id` в пути, JSON в теле | Полностью обновить информацию о фильме. Возвращает обновлённую запись. |
| DELETE | `/{movie_id}` | `movie_id` в пути | Удалить фильм по идентификатору. |

## Структура данных

Каждая запись о фильме содержит следующие поля:

| Поле | Тип | Описание |
|---|---|---|
| `id` | `int` | Уникальный идентификатор фильма. |
| `name` | `str` | Название фильма. |
| `plot` | `str` | Сюжет фильма. |
| `genres` | `List[str]` | Список жанров фильма, хранится в JSON-формате. |
| `casts` | `List[str]` | Список актёров, хранится в JSON-формате. |

Пример JSON для добавления или обновления фильма:

```json
{
  "name": "Космическая одиссея 2001 года",
  "plot": "Обезьяны увидели монолит и стали эволюционировать.",
  "genres": ["Научная фантастика", "Триллер"],
  "casts": ["Кир Дулли", "Гари Локвуд"]
}
```

Идентификатор `id` создаётся автоматически при добавлении фильма и не передаётся в теле запроса.

## Валидация (Pydantic)

- `name` и `plot` — обязательные непустые строки.
- `genres` — обязательный непустой список строк.
- `casts` — обязательный непустой список строк.

При передаче некорректных данных возвращается HTTP 422 Validation Error.

При попытке получить, обновить или удалить фильм с несуществующим идентификатором возвращается HTTP 404 с сообщением `Movie with given id not found`.

## База данных (SQLite)

Для хранения информации используется база данных `movies.db`.

Таблица `movies` содержит следующие столбцы:

- `id` — первичный ключ, идентификатор фильма;
- `name` — название фильма;
- `plot` — сюжет фильма;
- `genres` — JSON-массив жанров;
- `casts` — JSON-массив актёров.

SQLAlchemy используется для выполнения операций добавления, получения, обновления и удаления записей.

Сессии базы данных создаются для обработки запросов и закрываются после завершения работы с ними.

## HTTP-статусы

| Код | Описание |
|---|---|
| `200` | Успешное получение или обновление данных. |
| `201` | Фильм успешно добавлен. |
| `204` | Фильм успешно удалён. |
| `404` | Фильм с указанным идентификатором не найден. |
| `422` | Ошибка валидации входных данных. |
